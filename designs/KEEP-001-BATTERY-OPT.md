## 1. 外壳空间与电池选型分析

### 1.1 可用空间估算

外壳外部尺寸: 78 × 48 × 12 mm
内部可用尺寸（扣除 1.2mm 壁厚×2）: 约 75.6 × 45.6 × 10.8 mm
PCB 厚度: 1.0mm（4层板标准厚度）
电池堆叠高度约束: 10.8mm - 1.0mm（PCB）- 1.5mm（顶部缓冲/绝缘）= **8.3mm 最大电池厚度**

### 1.3 推荐电池规格

**第一推荐: 703048 聚合物锂电池**

| 参数 | 值 |
|------|-----|
| 型号 | 703048 |
| 尺寸 | 7.0 × 30.0 × 48.0 mm |
| 标称容量 | 800 mAh (典型) / 780 mAh (最小) |
| 充电截止电压 | 4.2V |
| 放电截止电压 | 3.0V |
| 最大持续放电 | 1C (800mA) |
| 工作温度 | -20°C ~ 60°C |
| 保护板 | 需集成 NTC + 过充过放保护 |

**为何是 703048 而非更大:**

1. 7.0mm 厚度留出 1.3mm 缓冲（8.3mm - 7.0mm = 1.3mm），保障外壳合模不会压迫电池
2. 30×48mm 宽长边比充分利用下半区空间
3. 800mAh 是 450mAh 的 **1.78 倍**，对续航有质的改善
4. 703048 是标准规格，多家供应商（ATL/珠海冠宇/赣锋锂业）均有量产，单价约 ¥8-12

**备选: 603048（600mAh）** — 如果结构验证 7mm 厚度有干涉，退而求其次

### 1.4 电池扩容带来的续航增益

| 电池 | 容量 | 相对增益 |
|------|------|---------|
| 503040（原方案） | 450mAh | 基准 |
| 603048（备选） | 600mAh | +33% |
| **703048（推荐）** | **800mAh** | **+78%** |

## 3. 省电策略

### 3.1 定位层 (GNSS) 省电

#### 3.1.1 动态定位频率

利用 Air780E 内置 GNSS + 加速度计（外部新增），实现基于运动状态的自适应频率:

```
┌─────────────────────────────────────────────────────────┐
│                    运动检测状态机                          │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  [静止] ──(加速度计检测到运动)──> [运动中] ──(静止>5min)──> [刚静止] │
│    │                              │                      │   │
│    │  GPS 关闭                     │  GPS+4G 正常频率     │   │
│    │  仅 LBS Cell ID 心跳          │  (1次/N分钟)         │   │
│    │  上报频率: 30min/次           │                      │   │
│    └──────────────────────────────┘                      │
│                                                         │
│  [刚静止] ──(静止>15min)──> [静止]                         │
│    │  GPS 延续 1-2 次确认静止                             │
│    │  减速上报                                            │
│    └──────────────────────────────────────────────────────┘
```

**策略参数:**

| 状态 | GPS 状态 | 定位方式 | 上报频率 | 说明 |
|------|---------|---------|---------|------|
| 静止 | 关闭 | LBS 基站定位 | 30 分钟/次 | 省电核心 |
| 运动中 | 开启 (Tracking) | GPS + LBS | 5 分钟/次 | 日常追踪 |
| 刚静止（0-15min） | 开启（降频） | GPS + LBS | 10 分钟/次 | 过渡态避免频繁开关 |
| SOS 触发 | 强制开启 | GPS | 实时连续 | 紧急模式 |

#### 3.1.2 GPS 辅助加速 (AGPS / 星历辅助)

- Air780E 支持 AGPS（网络辅助定位），通过 4G 网络下载星历数据
- 热启动时间从 35s（冷启）降至 5-8s
- 每次定位功耗降低 **85%**（0.34 mAh → 0.05 mAh）
- 实现方式: 每次 4G 通信时同步获取星历，存储在 GNSS 芯片 SRAM

#### 3.1.3 GNSS 电源管理

- 软硬件实现 GNSS 模块供电独立控制: Air780E 的 GNSS 部分可通过 AT 命令 `AT+CGNSPWR=0` 完全关闭
- 静止状态下完全切断 GNSS 供电 → **0mA 待机**

### 3.2 通信层 (4G LTE) 省电

#### 3.2.1 3GPP 标准省电模式

Air780E 支持 Cat.1 标准的两种省电模式:

**PSM (Power Saving Mode) — 核心省电手段**

| 参数 | 建议值 | 说明 |
|------|-------|------|
| T3412 (周期性TAU) | 54 分钟 | 设备最长可 54 分钟不联网 |
| T3324 (Active Timer) | 10 秒 | 发送后等待下行数据的窗口 |
| PSM 深度睡眠电流 | 3~5 μA | 相当于关机电流 |

**eDRX (Extended Discontinuous Reception) — 补充方案**

| 参数 | 建议值 | 说明 |
|------|-------|------|
| eDRX Cycle | 20.48s | Cat.1 最大周期 |
| Paging Time Window | 1.28s | 监听寻呼的窗口宽度 |
| eDRX 平均电流 | 0.5~2mA | 远低于正常待机 20mA |

#### 3.2.2 推荐 4G 省电配置

```
PSM 模式（默认使用）:
  - AT+CPSMS=1,,,"00001000","00000101"
  → T3324 = 10秒（active timer）
  → T3412 = 54分钟（TAU周期）

eDRX 模式（PSM 不可用时的回退）:
  - AT+CEDRXS=1,5,"1011"
  → eDRX cycle = 20.48s
```

#### 3.2.3 MQTT 心跳优化

| 优化项 | 建议 | 省电收益 |
|-------|------|---------|
| 心跳频率 | 从 60s → 与上报周期相同（无需额外心跳） | 减少 50%+ 的冗余联网 |
| Keep Alive | 设为 300s（5分钟） | 减少 PINGREQ 频率 |
| QoS 等级 | 常规上报 QoS 0，SOS 使用 QoS 1 | QoS 0 无 ACK 等待，省电 40% |
| Payload 压缩 | 使用 CBOR 或自定义二进制打包 | 减少 60-70% 无线数据量 |
| 批量上报 | 在 4G 连接窗口内聚合发送多个数据点 | 1 次连接传多个数据 |

### 3.3 MCU 层 (ESP32-S3) 省电

#### 3.3.1 深度睡眠模式

```
正常工作时序:
┌──────────────────────────────────────────────────────────┐
│  [深度睡眠] ──→ [RTC唤醒] ──→ [GPS定位] ──→ [4G上报] ──→ [深度睡眠] │
│      ~8μA        <1ms           ~7s           ~2s          ~8μA    │
│     (周期内)     (MCU启动)    (GNSS+解析)    (MQTT发送)    (周期内)    │
└──────────────────────────────────────────────────────────┘
```

**ESP32-S3 深度睡眠参数:**

| 配置 | 电流 | 说明 |
|------|------|------|
| 默认深度睡眠 | 5~10 μA | RTC 定时器唤醒 + GPIO 唤醒 |
| 深度睡眠 + ULP 协处理器 | 10~25 μA | ULP 可轮询加速度计状态 |
| 深度睡眠 + RTC 内存保留 8KB | 5 μA | 保留 Wi-Fi 快速连接信息 |
| Modem Sleep | 3~5 mA | 不推荐（不需要保持 Wi-Fi） |

**推荐配置:**

```
- 使用深度睡眠（非 Modem Sleep）
- 启用 RTC 定时器（定时唤醒执行定位周期）
- 启用 GPIO 外部中断唤醒（SOS 按键可中断深度睡眠）
- 保留 8KB RTC 内存（存状态机信息、下次唤醒时间）
```

#### 3.3.2 MCU 工作频率优化

| 场景 | CPU 频率 | 电压 | 内核数 | 电流 |
|------|---------|------|-------|------|
| 定位计算 (NMEA解析) | 80MHz | 0.9V | 单核 | ~30mA |
| MQTT 组包 + 4G AT 通信 | 80MHz | 0.9V | 单核 | ~30mA |
| 空闲等待 | 40MHz | 0.8V | 单核 | ~15mA |
| 深度睡眠 | N/A | 关闭 | N/A | ~8μA |

> **建议: 日常工作使用 80MHz 单核模式，比 240MHz 双核省电 60%**
> NMEA 解析和 AT 通信是 I/O 密集型，不是 CPU 密集型，80MHz 绰绰有余

### 3.4 加速度计辅助省电

新增低成本加速度计（如 LIS3DH / ADXL345 / BMA400，单价 ¥2-5）:

| 功能 | 实现方式 | 省电收益 |
|------|---------|---------|
| 运动唤醒 | 静止时加速度计中断唤醒 MCU | 避免 GPS 在静止时空转 |
| 静止判断 | 加速度计持续采样（2μA） | GPS 关闭，只靠 LBS |
| 计步检测 | 低功耗计步（可选） | 不需要 GPS 也知道"在动" |

**加速度计选型建议:**

| 型号 | 工作电流 | 休眠电流 | 特性 | 价格 |
|------|---------|---------|------|------|
| LIS3DH | 2~10μA | <1μA | I2C/SPI, 运动检测中断 | ¥2-3 |
| ADXL345 | 23μA | 0.1μA | I2C/SPI, 成熟稳定 | ¥3-5 |
| BMA400 | 4μA | 0.1μA | 超低功耗, 内置计步 | ¥4-6 |

**推荐: LIS3DH**（性价比最优，2μA 工作电流，运动中断唤醒）

### 3.5 软件优化

| 优化项 | 说明 | 预估收益 |
|-------|------|---------|
| NMEA 轻量解析 | 仅解析 $GNGGA/$GNGLL，跳过 $GPGSV 等明细 | 减少 30% GPS 处理时间 |
| MQTT 最小 payload | 不传冗余字段；枚举值代替字符串 | 减少 50%+ 无线传输时间 |
| 断线重连策略 | 指数退避 (1s/2s/4s/8s/32s/300s max) | 避免频发重连耗电 |
| 静默检测 | 多周期无位置变化则主动降频 | 自适应省电 |

## 4. 预期续航计算

### 4.1 场景定义

定义 5 种典型上报策略:

| 策略 | 运动时上报频率 | 静止时上报频率 | GPS 热启动 | 4G PSM | 说明 |
|------|--------------|--------------|-----------|--------|------|
| **A** (当前方案) | 1 次/分钟 | N/A | 否（冷启） | 无 | 原方案基线 |
| **B** (低配省电) | 5 次/分钟 | 1 次/30分钟 | 是 | 启用 | 无加速度计 |
| **C** (推荐方案) | 1 次/5分钟 | 1 次/30分钟 | 是 | 启用 | 含加速度计 |
| **D** (极致省电) | 1 次/10分钟 | 1 次/60分钟 | 是 | 启用 | 牺牲部分实时性 |
| **E** (混合 SOS) | 1 次/5分钟 + SOS实时 | 1 次/30分钟 | 是 | 启用 | 推荐 + SOS 保证 |

### 4.2 每日功耗分解

**假设:**
- 运动/静止比例 = 30% / 70%（典型日常: 儿童上学 8h 轻微运动 + 16h 静止）
- 每日数据: 24h = 1440 分钟
- 每次 GPS 定位（热启动 + Tracking 5s）= 0.05 mAh
- 每次 4G MQTT 上报（PSM 唤醒 + 发送）= 0.08 mAh
- 静止期仅 LBS（Cell ID）+ 加速度计 = 忽略不计

#### 策略 C 单日耗电计算（推荐方案）

**运动期间 (30% = 432 分钟/天):**
- 上报频率: 1次/5分钟 → 86.4 次/天
- 每次耗电: 0.05 mAh (GPS) + 0.08 mAh (4G) = **0.13 mAh**
- 运动日耗电: 86.4 × 0.13 = **11.23 mAh**

**静止期间 (70% = 1008 分钟/天):**
- 上报频率: 1次/30分钟 → 33.6 次/天
- 每次耗电: LBS = 0 (基站信息无额外 GNSS 功耗) + 0.06 mAh (4G 小包) = **0.06 mAh**
- 静止日耗电: 33.6 × 0.06 = **2.02 mAh**

**MCU 深度睡眠 (周期内 ~7 分钟 x 86.4 = 余量):**
- 日深度睡眠时间 ≈ 24h - 86.4×(7s+2s) - 33.6×1s ≈ 23.77h
- 深度睡眠功耗: 8μA × 23.77h ≈ **0.19 mAh**

**加速度计工作:**
- 2μA × 24h = **0.048 mAh** （忽略不计）

**4G PSM 待机功耗:**
- PSM 期间 5μA × ≈23.5h = **0.12 mAh**（实际上大部分时间在 PSM）

**偶尔冷启动/重连（假设每天 1 次）:**
- 1 × 1.0 mAh = **1.0 mAh**

**单日总耗电 (策略 C):** 11.23 + 2.02 + 0.19 + 0.12 + 1.0 = **14.56 mAh**

**电池容量: 800 mAh (703048) / 可用容量按 90% 算 = 720 mAh**

| 策略 | 运动频率 | 静止频率 | 单日耗电 | 理论续航 | PRD 达标? | 说明 |
|------|---------|---------|---------|---------|----------|------|

**全部运动状态 (100% 运动, 儿童全天户外活动)**

### 4.5 SOS 紧急模式功耗

SOS 长按触发后，设备进入紧急模式:
- GPS 持续定位: 25mA
- 4G 连续上报 (1次/3s): 200mA × 0.3 duty cycle ≈ 平均 60mA
- 合计平均电流: ≈85mA
- SOS 持续 1 小时耗电: 85 mAh
- SOS 持续 2 小时耗电: 170 mAh

**结论:** SOS 紧急模式不宜连续开启超过 2 小时（消耗 20%+ 电量）。
建议 SOS 稳定持续 5-10 分钟后自动恢复为常规模式。

## 5. PCB 布局建议

### 5.1 电池区域最大化方案

**当前布局（原方案 503040）:**
```
┌─────────────────────────────────────┐
│  ┌──────────────────────────┐        │  ← 48mm
│  │      PCB (上半区)         │        │
│  │   MCU + 4G模组 + 天线    │        │
│  └──────────────────────────┘        │
│  ┌──────────────────────────┐        │
│  │    503040 电池 450mAh     │        │
│  │    5×30×40mm             │        │
│  └──────────────────────────┘        │
└─────────────────────────────────────┘
```

**优化布局（推荐 703048）:**
```
┌─────────────────────────────────────┐
│  ┌──────────────────────────┐        │  ← 48mm
│  │  PCB  75.6×24mm          │        │
│  │  ESP32-S3 + Air780E       │        │
│  │  + Type-C + SOS 按键     │        │
│  │  + LED×2 + 振动马达      │        │
│  └─────────┬────────────────┘        │
│            │ 20mm                    │
│  ┌─────────┴────────────────┐        │
│  │  703048 电池 800mAh       │        │
│  │  7×30×48mm               │        │
│  │  (向两侧延伸, 厚 7mm)     │        │
│  └──────────────────────────┘        │
│  ┌──────────────────────────┐        │
│  │  MK 20×14mm 喇叭          │        │
│  │  (或移至上角)              │        │
│  └──────────────────────────┘        │
└─────────────────────────────────────┘
```

### 5.2 具体调整建议

| 调整项 | 原方案 | 新方案 | 说明 |
|-------|-------|-------|------|
| PCB 尺寸 | 48×40mm | 75.6×24mm 狭长L形 | 上半区仅占 24mm 高度，给电池更多宽度 |
| 电池位 | 下半区中央 30×40mm | 下半区偏下 30×48mm | 延伸至最宽 48mm |
| 电池厚度 | 5mm (503040) | 7mm (703048) | 厚度增加 40%，容量+78% |
| 喇叭位置 | 左下角 | 右上角或底部侧边 | 避开电池增长区域 |
| Type-C 位置 | 侧边中间 | 上侧边 | 不干扰电池区域 |
| 加速度计 | 预留焊盘 | LIS3DH 直接贴片 | ¥2-3 成本换 3× 续航 |

### 5.3 关键结构注意事项

1. **电池与 PCB 间距** — 保留至少 1.5mm 间隙防止短路和应力
2. **电池缓冲泡棉** — 电池上方贴 0.5mm 压缩泡棉，吸收公差
3. **NTC 热敏电阻** — 电池必须集成 NTC（10kΩ B=3435），用于充电温度保护
4. **天线隔离** — 4G 主天线和 GPS 陶瓷天线 距离 ≥ 20mm，位于 PCB 两端
5. **喇叭腔体** — 如电池 7mm + PCB 1mm + 底部 1.5mm 绝缘 = 9.5mm → 12mm 余量 2.5mm 可做喇叭后腔

## 6. 结论与折衷方案

### 6.1 能否达成 7 天目标？

**结论: 完全可以，且有较大余量。**

| 组件 | 优化前 | 优化后 |
|------|-------|-------|
| 电池容量 | 450 mAh | 800 mAh (+78%) |
| GPS 模式 | 冷启动每次 35s | 热启动每次 5s (-86%) |
| 运动上报 | 1次/分钟 | 1次/5分钟 (-80%) |
| 静止策略 | 无（同样频率） | GPS 关闭，仅 LBS 30min/次 |
| 4G 省电 | 无 PSM | PSM 深度睡眠 (5μA) |
| MCU 模式 | 活跃待机 | 深度睡眠 + 定期唤醒 |
| 加速度计 | 无 | 运动检测唤醒 |
| 理论续航 | ~2 天 | **~49 天（保守 19 天）** |

### 6.2 推荐执行方案

```
第一优先级（必须做，直接决定续航能否达标）:
  [P0] 电池升级: 503040→703048 (450→800mAh)
  [P0] 动态定位频率: 运动 1次/5min, 静止 1次/30min
  [P0] 4G PSM 模式配置（3~5μA 待机）
  [P0] GPS 电源独立控制（静止时关闭 GNSS）
  [P0] MCU 深度睡眠模式（8μA 待机）

第二优先级（大幅提升续航，硬件成本增加 ¥2-3）:
  [P1] 新增加速度计 LIS3DH（运动检测自动切换频率）
  [P1] AGPS 星历辅助（缩短 GPS 定位时间至 5s）

第三优先级（锦上添花，约 10-20% 额外增益）:
  [P2] MQTT payload 二进制压缩
  [P2] 批量上报（4G 连接窗口聚合）
  [P2] 深度睡眠保留 WiFi 连接信息加速
```

### 6.3 折衷方案

如果 703048（7.0mm）因结构原因无法通过，退一步采用 603048（6.0mm, 600mAh）:

| 策略 | 600mAh 可用 540mAh | 续航 |
|------|-------------------|------|
| C (推荐) 100%运动 | 540/37.4 | 14.4 天 ✅ |
| C (推荐) 30%运动 | 540/14.6 | 37.0 天 ✅ |

> 即使只用 600mAh 电池，配合省电策略仍可远超 7 天目标。

### 6.4 成本影响汇总

| 变更项 | 单价影响 | 一次性投入（NRE） |
|-------|---------|-----------------|
| 503040→703048 电池 | +¥3~5 | - |
| 新增 LIS3DH | +¥2~3 | - |
| PCB 重新布局 | 不变 | ¥2000-5000（Layout + 打样） |
| 固件开发（省电策略） | - | 约 40h 开发工时 |
| **单台 BOM 成本增额** | **+¥5~8** | - |
