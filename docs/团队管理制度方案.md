## 一、团队架构

```
         陈总（产品决策人）
              │
          OpenClaw（项目经理）
          ┌────┼────┐
          │    │    │
       子Agent 子Agent 子Agent
       (硬件)  (小程序) (后端)
```

## 二、核心制度

### 2.1 开发流程
```
写方案 → 审批 → 开发 → 审查 → 验证 → 入库
```

### 2.2 代码审查
- 每个子Agent的代码由**另一个子Agent验证**
- 不能自己写自己验

### 2.3 资料库
```
~/projects/keepsafe/
├── docs/         产品文档+开发方案
├── src/          源代码（固件/小程序/后端）
├── meetings/     会议纪要
├── releases/     发布版本
├── team/         团队管理+制度
├── specs/        技术规格书
└── shared-memory/ 共享记忆（决策/踩坑/术语）
```

### 2.4 共享记忆
- 每次技术决策记录在 `decisions.md`（选了什么+为什么）
- 每次踩坑记录在 `lessons.md`（问题+原因+解决）
- 新人/Agent来了，一读就懂

### 2.5 交付方式
- **陈总只管看结果**，不过问技术细节
- 每周一份进度报告
- 需要决策时我会明确问
