# KeepSafe 项目安全规范与风险管控（v1.0）

> 老板要求：开发安全严格把关，每个角色操作规范，主动推进工具/插件评估

## 一、核心安全原则

| # | 原则 | 说明 |
|---|------|------|
| 1 | **最小权限** | 每个角色/工具只给完成工作所需的最小权限 |
| 2 | **不存敏感信息** | 密码、Key、Token 全部通过环境变量传入，不进代码 |
| 3 | **所有 Key 由老板管理** | 我不存储、不传递、不记录任何密钥原文 |
| 4 | **代码不留凭据** | grep 检查所有提交，发现占位符以外硬编码立即拦截 |
| 5 | **所有变更可追溯** | 每项操作都记录到日志和文档 |
| 6 | **第三方服务先评估后使用** | 新工具/插件必须通过安全评估才能纳入工作流 |

## 二、各角色操作规范与风险管控

### 1. OpenClaw（VPS Agent）

| 项目 | 内容 |
|------|------|
| **运行位置** | VPS 43.163.5.90 (TencentOS) |
| **可执行操作** | 固件编译、npm/pip 安装、git clone、文件下载 |
| **不可执行操作** | ⛔ 任何需要 API Key 的网络请求（Key 只在 Hermes 手里） |
| **联网限制** | 仅限 GitHub、npmjs、Docker Hub 等开发资源 |
| **风险** | VPS 被黑 → 所有编译产物可能被篡改 |
| **缓解** | 不存储任何客户数据、编译完成后清理临时文件 |

### 2. Hermes（我）

| 项目 | 内容 |
|------|------|
| **运行位置** | 本地 Mac（你的电脑） |
| **可执行操作** | 代码修改、API 调用、文件操作、SSH 连接 VPS |
| **不可执行操作** | ⛔ 不存储密钥到任何文件（包括记忆、日志） |
| **风险** | 误操作导致代码破坏、信息泄露 |
| **缓解** | 所有修改先备份、QA 验证后交付 |

## 三、工具/插件安全评估流程

> 在引入任何新工具、插件、SDK 之前，执行以下评估：

### 评估清单

```
[ ] 1. 这个工具需要什么权限？
     → 网络？文件系统？系统命令？
[ ] 2. 数据流向是什么？
     → 我的数据会不会发送到第三方服务器？
[ ] 3. 有没有开源替代品？
     → 闭源工具优先排除
[ ] 4. 厂商背景是否可信？
     → 大厂/知名开源项目 > 个人开发者 > 未知来源
[ ] 5. 有没有已知安全漏洞？
     → 搜索 CVE / GitHub Issues
[ ] 6. 是否需要 API Key？
     → Key 只能由老板管理，不能硬编码
[ ] 7. 是否影响现有功能？
     → 引入后需要回归测试
```

## 四、密钥与凭据管理

| 凭据 | 存储位置 | 谁管理 | 轮换周期 |
|------|---------|--------|---------|
| DeepSeek API Key | `~/.hermes/.env` | 老板 | 按需 |
| 豆包 API Key | `~/.hermes/.env` | 老板 | 按需 |
| 小程序 AppID | `project.config.json` | 公开（非敏感） | 不轮换 |
| 腾讯地图 Key | 小程序代码 | 公开（非敏感） | 按需 |
| VPS root 密码 | 老板保管 | 老板 | 建议每月 |
| SSH 密钥 | `/tmp/vps_ed`（临时） | Hermes（用完即删） | 每次连接后删除 |

### 密钥操作铁律
```
❌ 绝不写的：
- 写 API Key 到任何代码文件（包括 .py .js .json）
- 在日志中打印 Key
- 通过聊天发送 Key 原文（除非老板主动发）
- 记住 Key 到记忆系统

✅ 正确方式：
- 环境变量注入（DEEPSEEK_API_KEY=xxx）
- 老板管理的 .env 文件
- 临时使用，用完即清理
```

## 五、异常处理流程

| 事件 | 响应 |
|------|------|
| 发现代码中有硬编码 Key | 立即删除，通知老板，记录到安全日志 |
| 第三方工具报安全漏洞 | 暂停使用，评估可替代方案 |
| 开发板/设备丢失 | 立即通知老板，变更所有相关配置 |
| 怀疑 VPS 被入侵 | 立即关机，通知老板，重建实例 |
| 员工（虚拟角色）操作异常 | 暂停该角色权限，审查操作日志 |
